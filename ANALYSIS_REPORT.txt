1. PROJECT OVERVIEW
================================================================================

low_poly_3d is a single-page browser app that turns an "LBL blueprint"
(declarative JSON or a hand-written .ts module) into a live, editable
Three.js scene. Project name says "low poly" but the system supports ANY
style (low-poly, mid-poly, high-poly, smooth-shaded, voxel, toon, photoreal,
hand-painted, retro-PSX, etc.).

Layout:
  - index.html           — 1.6 MB monolith, the whole renderer + UI
  - mockup-generator.html — 84 KB sibling "model store" UI
  - public/aces/         — 7 files, 113 KB — ACES engine (anyCreature port)
  - public/modeling/     — 9 files, 198 KB — 44-Technique MT bundle
  - public/rig/          — 14 files, 125 KB — skeleton templates,
                            anycreature compiler, three-rig-helpers bundle
  - public/models/       — 10 files, 512 KB — 9 .ts demo models + manifest
  - 6 reference docs in repo root — 6.6 MB combined
  - .github/workflows/manifest.yml — auto-regenerates public/models/manifest.json

External runtime dependencies (CDN, via import map):
  - three@0.160.0
  - three/addons/* (OrbitControls, TransformControls, GLTFExporter, RoundedBoxGeometry,
    DecalGeometry, ConvexGeometry, MarchingCubes, SimplifyModifier, BufferGeometryUtils,
    EffectComposer, RenderPass, UnrealBloomPass, OutputPass, Pass, FullScreenQuad,
    SSAOPass, RoomEnvironment, GLTFLoader, FBXLoader, OBJLoader, STLLoader, ColladaLoader)
  - three-mesh-bvh@0.9.3
  - three-bvh-csg@0.0.16
  - fflate@0.8.2  (zip support)

Spec target advertised: 4 different version numbers across the repo
(see Section 8 for the inconsistency table).

2. RENDERER CAPABILITIES (index.html, 31 389 lines, 1.6 MB)
================================================================================

The renderer is one ES module. Top-down structure:

2.1  Module bootstrap
     - <script type="importmap"> resolves "three", "three/addons/", and 14
       local specifier aliases (aces-*, mt-*, three-rig-helpers, anycreature-
       compiler) to either CDN URLs or local public/* paths.
     - The single <script type="module"> block has the entire renderer in
       one closure-less module. ~504 named function declarations plus
       ~200 const/let top-level bindings.

2.2  Three.js scene + camera + controls
     - WebGLRenderer (antialias, ACESFilmic tonemap, PCFSoftShadowMap,
       shadowMap 2048x2048). setPixelRatio min(devicePixelRatio, 2).
     - PerspectiveCamera 45° fov, near 0.05, far 2000.
     - OrbitControls with damping, autoRotate 0.5 deg/s.
     - 5-light rig: ambient (0.5), hemi (sky/ground 0.8), directional sun
       (2.4, casts shadows), fill (0x7f40ff, 1.0), rim (0x4fc3f7, 0.4),
       back-left rim (0xaaccff, 0.8).
     - GridHelper 60x60 with renderOrder=1 (renders after scene).
     - 4 lighting presets (Studio / Outdoor / Night / Flat), cycle button.
     - Dark + light themes (CSS variable swap).

2.3  Post-processing (EffectComposer)
     - RenderPass → SSAOPass (off by default) → UnrealBloomPass (strength 0.55)
       → OutputPass.
     - Custom screen-space outline shader (depth+normal edge detect) as
       alternative to backface-expansion outline. ~50 lines of GLSL.
     - Two outline modes: 'backface' (default) and 'screenspace'.
     - PMREMGenerator + RoomEnvironment (procedural IBL, no .hdr file).
     - Per-style tone-mapping table (NoToneMapping for voxel/toon/flat,
       ACESFilmic for realistic, Cineon for stylized/chibi, Linear for painterly).

2.4  Materials / textures (PBR pipeline)
     - buildMaterial() / buildMaterialRaw() honour per-object material id,
       color, roughness, metalness, transmission, ior, sheen, clearcoat,
       emissive, emissiveIntensity, normalScale, opacity, transparent.
     - Material presets: MAT_DB (60+ keys: fabric/leather/wood/metal/glass
       /stone/plastic etc.), CS2_PBR (9 finish styles + 5 wear tiers:
       FN/MW/FT/WW/BS, 8 new MAT_DB presets, MeshPhysicalMaterial extras:
       iridescence, iridescenceIOR, iridescenceThicknessRange, specularIntensity,
       specularColor, attenuationColor, attenuationDistance).
     - Procedural texture generators (no external assets):
       microRoughnessMap, punctateMaps, striateMaps, heightField→normal/
       /roughness/ao/curvature/cavityDirt, bricks/Truchet/Cairo/splatter
       patterns, gradient/matcap/toon/contact-shadow textures.
     - Image-texture pipeline (data-URLs only, no network fetch).
     - Cavity-shading / color-variation / edge-split / smoothing-groups /
       subdivision on per-object userData flags.

2.5  Geometry pipeline
     - buildGeometry() dispatches to 60+ primitive builders (buildFrustumBox,
       buildWedge, buildArch, buildRoofPlane, buildStair, buildFrame, buildArc,
       buildHelix, buildSpiral, buildCurve, buildHill, buildMountain, buildCliff,
       buildPlateau, buildValley, buildRockFormation, buildCave, buildTreeTrunk,
       buildBranch, buildRoot, buildLeaf, buildPetal, buildFlower, buildGrassBlade,
       buildVine, buildSeed, buildFruit, buildBlob, buildEgg, buildTeardrop,
       buildHorn, buildAntler, buildClaw, buildBeak, buildFin, buildWing,
       buildFeather, buildTentacle, buildStar, buildHeart, buildGem,
       buildCrystal, buildDiamond, buildLantern, buildBanner, buildGear …).
     - Loopsubdivide (Catmull-Clark-like) on per-mesh flag.
     - CSG (three-bvh-csg) lazy-loaded for boolean ops.
     - DecalGeometry for surface-projected decals.
     - Convex hull (ConvexGeometry) and Marching Cubes (SDF/voxel).
     - 50+ animation/easing falloff curves, helix/spiral path builders.

2.6  Animation system
     - THREE.AnimationMixer + THREE.AnimationClips.
     - lblCollectAnimations() pulls clips from 4 sources in priority order:
       1. gltf.animations (GLTFLoader)
       2. root.animations (FBX/Collada loaders)
       3. rt.animations.clips (modern TS factories — Model_3, _4, _6, _7, _9)
       4. rt.animations.mixer.getActions() (also modern path)
       5. rt.animations as a plain [{name, duration, tracks:[…]}] array
          (legacy hint path — Model_2 publishes this; renderer builds
          new NumberKeyframeTracks from the descriptors, **losing original
          VectorKeyframe/QuaternionKeyframe type** — see Problem #18)
     - Dedup by clip.uuid AND clip.name.
     - Silences any pre-existing mixer on the loaded root (stops actions,
       uncaches, calls root.stop() if present) so only the in-app mixer
       runs.
     - Pose snapshot/restore for the pause button.
     - Play/pause + cycle-next UI (panel hidden when no clips).
     - normalizeClipForGlb() rewrites Euler-axis tracks ("*.rotation[x|y|z]")
       into a single quaternion track, with FPS resampling, end-time clamp,
       and shortest-arc continuity.
     - _stripEmptyBufferViewsFromGLB scrubs zero-length bufferViews that
       GLTFExporter occasionally writes.

2.7  Rigging integration
     - three-rig-helpers bundle (3.9 KB minified, ESM) provides 9 helpers:
       buildSkeleton, resetSkeleton, jointWorldPosition, validateRigGraph,
       asVector, buildSemanticWeights, buildRigidSemanticWeights,
       validateWeights, buildGeodesicWeights, buildHeatDiffusionWeights,
       buildInverseDistanceWeights, buildSegmentationWeights.
     - PART 75.1 dispatch in __lblApplySkinWeights() — 6-value enum:
       "semantic" | "rigid" | "geodesic" | "heat-diffusion" | "inverse-distance" | "segmentation".
     - PART 76.3: lazy-load skeleton templates from public/rig/skeletons/*.json
       and auto-scale to model bounding box.
     - PART 77: Mixamo bone remap (21-entry preset), __lblRemapAnimationClip()
       rewrites track names at import time.
     - PART 78/79/85: voxel/pose/cloud auto-riggers (declared STUBS).
     - PART 81: chain-curvature animation (Sin+Perlin per chain root).
     - PART 82: 12-constraint post-pass catalog.
     - 30-bone canonical catalog (CANONICAL_BONE_CATALOG_30).
     - BVH-accelerated raycast (lazy-loaded three-mesh-bvh).

2.8  ACES integration (PART 90)
     - Eagerly imports 7 ACES sub-modules at startup.
     - #aces-btn in toolbar → ACES panel → ACES.run(scene, opts).
     - 6-stage pipeline: extract → crease split + angle-weighted normals →
       AO bake → L1-L8 OKLab stack → L8 bone-field normal softening →
       25 mechanical checks → write-back to live BufferGeometry.
     - Check report renders in the panel + feeds the validator log.

2.9  44-Technique MT bundle (PART 100-143)
     - Same eager-import pattern as ACES.
     - #mt-btn → MT panel (sections, catalog). MT.run(name, target, opts)
       / MT.runStack / MT.applyToScene / MT.selfTest.

2.10 UI / panel architecture
     - Left panel: object tree + Inspector (Properties / Triangles / Fidelity
       tabs). Right panel: top toolbar + view + postprocess controls +
       fidelity chip. Bottom: animation strip + status pill.
     - Modal overlays: prompt builder (PART 52.1), compare (PART 52.2),
       keyboard shortcuts.
     - ACES panel + MT panel lazy-built.
     - 60-step undo/redo via buildScene wrapper.
     - Box-select, gizmo (TransformControls), grid, multi-select groups.
     - Theme toggle (dark/light), lighting preset cycle, view presets.
     - Compare mode (reference image overlay), silhouette IoU grading.
     - Model store (preload via mockup-generator.html).

2.11 Validation
     - validateBlueprintSchema() — JSON schema check.
     - lblValidateAgainstSpec() — 36 PART 32/65/38-46/67/74/100-143
       anti-pattern validators (E1..E36).
     - 9 fidelity-gate checks (STYLE MATCH, CATEGORY MATCH, COLOR/SILHOUETTE
       MATCH, DETAIL COUNT, METALLIC-PRESENCE, EMISSIVE-PRESENCE,
       STYLE-COHERENT-MATERIALS).
     - Triangle-budget tiers (10k/30k/100k with colour-coded bar).
     - Proportion-declaration gate.

2.12 Export / packaging
     - GLB (GLTFExporter with skin weight + animation track support,
       bufferView sanitization, name remap).
     - OBJ, STL.
     - GLB-with-rigged-skeleton (exportRiggedModelToGlb in Model_7).
     - .ts source dump, .zip bundle (model+rig+assets via fflate).

2.13 Other features
     - Group / ungroup / combine (group-pivot wrap).
     - Face-texture editor (per-face UV/transform).
     - Texture positioning (drag/scale on viewport).
     - Modular socket kitbash (PART 33.1[7]).
     - FSM (animation state machine) inspector.
     - 18-render multi-view validation grid (PART 44.7).
     - LOD chain generation (5-LOD, displayed in inspector).
     - T-pose, mesh cleanup, eye-tracking helpers.

3. ACES (anyCreature Engine Surface) — public/aces/
================================================================================

7 ES2020 classic scripts, 4 254 lines, 113 KB total. All attach to
window.ACES_* (no exports). Run in browser via dynamic import() in
index.html.

3.1  aces-engine.js (317 lines) — façade
     - acesQualityPass(ctx) — the single entry point.
     - ctx = { scene, shading, ao, smoothAngle, classMap, skipChecks,
              skeleton, spec, onReport, animsCompiled, checksOpts }
     - 6 steps: extract → crease split + angle-weighted normals → AO →
       L1-L8 stack → L8 bone-field softening → mechanical checks → write-back.
     - extractMeshes() converts Three.js Object3D tree to plain {V,F,C,N,AO,color,material,part,…} records.
     - extractSkeleton() walks SkinnedMesh.skeleton.bones; **uses
       root.THREE for Vector3** — fragile, see Problem #7.
     - applyToGeometry() writes COLOR_0 + NORMAL back to the live
       BufferGeometry (POSITION is never moved).

3.2  aces-oklab.js (148 lines)
     - s2l, l2s, lin2oklab, oklab2lin, hex2lin, lin2hex, inGamut
     - oklab2srgb, srgb2oklab, mixOK, chromaWalk, etc.
     - The "Why OKLab" docstring is excellent — explains why L and chroma
       are independent in OKLab (so brighten + saturate are two numbers,
       not a blend mode).

3.3  aces-normals.js (278 lines)
     - vertexNormals(V, tris) — angle-weighted (Meyer) vertex normals.
     - smoothSplit(V, tris, deg, attrs) — crease split; only duplicates a
       vertex when it really carries more than one smoothing group.
     - faceData, incidence, creaseShare, foldCount.
     - foldCount: faces whose per-vertex normal sum disagrees with face
       normal. Used by mesh_integrity check to catch twist/breakage.

3.4  aces-ao.js (206 lines)
     - bakeAO(meshes, cfg) — Möller-Trumbore hemisphere rays from every
       vertex against the whole mesh (uniform grid acceleration).
     - cfg: { samples, strength, radius, multiply, skip }.
     - Writes m.AO[v] + multiplies into m.C[v] (linear-light color).

3.5  aces-shade.js (472 lines)
     - shadeStack(meshes, ctx, info) — the 8-layer L1-L8 stack.
     - softenNormalsByBones(meshes, sk, opts) — L8 layer.
     - DEFAULTS documented as "settled values a measured run agreed on".

3.6  aces-checks.js (1 258 lines) — 25 named checks
     - BLOCK (legality):
       mesh_integrity, root_containment, part_attachment, touch, balance,
       size, proportion, limb_clearance, anim_integrity, attack_reach,
       faceted_body, mirror_distortion, part_overlap, part_seat, soft_mass
     - WARN (style, PART 99): value_order, contrast_adjacent, share_hierarchy,
       focal_contrast, saturation_area, thinnest_px48, sq_fill, mirror_sym,
       straight_max, tri_budget, bright_floor
     - runChecks() walks CHECK_ORDER, collects per-check blocks/warns/info.
     - opts.strict: warns become blocks.
     - Each check returns { blocks, warns, info }.

3.7  aces-bones.js (176 lines)
     - mirrorName(), JOINT_TAGS table, side-limb joint name convention
       (LArm1Sh, RFrontLeg1Kn).
     - exportNames(spec, sk), assetExtras(spec).
     - HARNESS_NAME='ACES (anyCreature Engine Surface)', HARNESS_VERSION='1.0.0'.

3.8  Module loading contract
     - Each module is a classic script wrapped in IIFE.
     - Top: reads `window.ACES_*` dependencies. The `const` destructure
       runs at module top level, so a module CANNOT load before its
       dependency sets the global.
     - Bottom: `window.ACES_xxx = api;` + CommonJS fallback (`module.exports`).
     - index.html imports them in this order:
         aces-oklab → aces-normals → aces-ao → aces-shade →
         aces-checks → aces-bones → aces-engine
     - This order is correct, but aces-ao/aces-checks/aces-shade/aces-engine
       all destructure the dependency top-level, so a reorder would
       throw "Cannot destructure property X of 'Y' as it is null" at
       load time. There is no graceful fallback. (See Problem #6.)

6. ANIMATION CODE STRUCTURE
================================================================================

6.1  Data flow at load time
     - User drops a file / picks a model / pastes a .ts module.
     - runTsBlueprint() (or load3DFile() for uploaded 3D) is invoked.
     - If model is .ts: pickTsFactory() picks create*Model OR default.
       TypeScript is compiled in-browser via `ts.transpileModule()` (no
       external TS server).
     - The model is mounted via addTsModelToScene(group).
     - lblCollectAnimations() runs:
         a) gltf.animations (if GLTFLoader produced a gltf object)
         b) root.animations (any loader)
         c) rt.animations.clips (modern TS path)
         d) rt.animations.mixer.getActions() (modern TS path)
         e) rt.animations as a plain array (legacy hint array)
     - Dedup by clip.uuid AND clip.name.
     - lblSilenceRootPreExistingAnimations() stops every pre-existing
       mixer so the lblAnim mixer is sole driver.
     - lblSnapshotPose() captures the rest pose.
     - lblAnim.mixer = new AnimationMixer(root); actions = clips.map(mixer.clipAction);
     - First action plays; rest are stopped.

6.2  Per-frame
     - animate() calls lblAnim.mixer.update(dt) when a mixer exists.
     - tsClock (THREE.Clock) is the canonical dt source for TS factories
       via tickAllTsModels(dt, elapsedTime).
     - Modern TS factories store their own THREE.AnimationMixer in
       rt.animations.mixer AND set userData.tick to mixer.update; the
       lblAnim system silences these on take-over so there's no double-tick.

6.3  Export path
     - exportGLB() collects all exportable clips via
       collectExportableClips(exportRoot, sourceClips).
     - Each clip is run through normalizeClipForGlb() which:
       - Drops clips with no live tracks.
       - For each node, detects euler-axis sub-tracks ("*.rotation[x|y|z]"),
         builds a master time grid (keyframe times ∪ fps-resampled times),
         converts to quaternions, and writes a single QuaternionKeyframeTrack.
       - Enforces shortest-arc continuity.
     - Other track types (Vector, Number, raw "*.rotation") pass through.

6.4  Authoring (TS factory) contract (PART 1)
     - export function create*Model(options): THREE.Group
     - Optional export function create*ModelLookDevLights(): THREE.Group
     - Allowed imports: 'three', 'three/addons/...', 'three/examples/jsm/...'
     - No side effects; deterministic for same (seed, options).
     - userData.sculptRuntime = { nodes, meshes, sockets, materials,
       actions, animation, detailInventory, landmarks, fidelity, …,
       animations: { clips, mixer, actions: actionMap } }
     - userData.tick = (dt) => mixer.update(dt) (or noop for static).
     - userData.isPickable = true, userData.partName = ... on every mesh.

6.5  Authoring (anycreature spec) contract (PART 97)
     - JSON shape: name, height, palette, shading, smooth_angle,
       joints (map of name → [x,y,z] or relational def), chains,
       attach, mirror, volumes, parts, animations, claims, …
     - Compiled by anycreature-compiler.js (described above).
     - v1 limitation: bones exist in scene graph but the meshes are
       not SkinnedMesh, so animations don't visibly deform the model.

Severity legend:

[B] #1  public/rig/skeletons/object.json has 4 root joints
────────────────────────────────────────────────────────────────────────
    validateRigGraph() and buildSkeleton() (in three-rig-helpers.js
    AND src/skeleton.ts) both enforce "exactly one root joint". The
    object template has 4 (Bone_Top / Bone_Bottom / Bone_Left /
    Bone_Right), so any model that opts into class="object" and uses
    the auto-scaled template will throw on buildSkeleton.

    SOLUTION: Either (a) add a real root parent to all 4 joints
    (e.g. a hidden "Bone_Center" at restPosition [0,0,0] with all 4
    children) and update the renderer template-loader to keep the
    "object" class but tolerate multi-root via a flag, or (b) make
    buildSkeleton/validateRigGraph multi-root-aware and add a new
    helper buildMultiRootSkeleton that picks the first non-parented
    joint as the implicit root, or (c) special-case class="object"
    in the renderer to skip the validator (consistent with the
    "anyCreature compiled" path, which already allows multi-root).

    Recommended: (a) — keeps the data model honest and explicit.

[B] #2  quadruped_light.json declared height (1.45) is 0.335 m off
────────────────────────────────────────────────────────────────────────
    The spec file says `"height": 1.45` (overall quadruped height in
    metres). The actual resolved Y range is 0.035 (LFrontToe) to 1.150
    (Skull) = 1.115 m. About 23% shorter than declared.

    SOLUTION: Either tighten the joint offsets so the resolved range
    matches the declared height (raise Chest, Skull, and Brow/Skull y
    by ~0.34), or change the declared `height` to 1.115 (or a value
    matching the actual silhouette). Make sure the toes are at y≈0
    and the head crown is at y≈1.45.

    Recommended: fix the joint offsets (it's a design-card example, so
    the actual silhouette is what people copy).

[H] #3  Anchor numbers in quadruped_light.json don't match the geometry
────────────────────────────────────────────────────────────────────────
    W_over_H, fill, leg_fraction, mass_thirds, head_share, belly_y_over_H
    are all declared but none match the actual joint layout. The
    `_template` field claims they are ANCHORS for designers to deviate
    from, but the spec never says how the values are *measured* (body
    arc length vs bbox length, etc.) and the AI has no way to verify
    which definition the anchor uses.

    SOLUTION: Add a `_measurement` block to the spec documenting the
    exact recipe for each anchor number:
       "W_over_H"        = body_arc_length / (max_y - toe_y)
       "fill"            = 1 - (toe_y / hip_y)
       "leg_fraction"    = (hip_y - toe_y) / hip_y
       "head_share_of_length" = head_arc_length / body_arc_length
    and either (a) recompute the numbers so they match the joint data
    in this file, or (b) change the joint data so the numbers hold.
    Also: only 2 of 7 anchors include the unit; the rest have an
    ambiguous name. Either rename (e.g. `fill_1_minus_belly_over_H`)
    or include the formula in the spec.

    Recommended: (b) — the existing data is the de-facto geometry, so
    adjust the joints (or the body chain order) so the numbers hold.

[M] #6  ACES module loading is fragile
────────────────────────────────────────────────────────────────────────
    aces-shade.js, aces-ao.js, aces-checks.js all do

        const { lin2oklab, oklab2lin, ... } = oklab;
